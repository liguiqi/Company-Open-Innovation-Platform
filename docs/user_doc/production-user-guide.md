# Open-Innovation-Platform生产环境用户操作手册

> 版本：V1.0
> 撰稿：Platform Team 2026年04月27日

> **特别说明**

1.  公开站访客。
2.  注册成为合作伙伴的外部用户。
3.  负责方案评审的评审员。
4.  负责内容、账号和需求维护的管理员。

## 4. 公开站使用说明

### 4.1 首页

首页用于完成首次引导，重点功能如下：

1.  顶部品牌区可切换深浅主题。
2.  首页首屏可直接进入“技术需求大厅”或“加入生态联盟”。
3.  “技术需求大厅”板块展示当前公开需求摘要，点击卡片可进入需求详情。
4.  “HeT 全球合作伙伴联盟”板块只展示精选合作伙伴，点击底部按钮可进入完整目录。
5.  “联合创新案例”板块可进入案例详情页。

### 4.2 技术需求大厅

地址：`/needs`

用户可完成以下操作：

1.  浏览全部公开需求。
2.  按领域筛选需求，当前分类包括 `电机控制`、`传感器技术`、`新材料 / 工艺`、`AI 与算法`。
3.  进入需求详情页查看标题、需求编号、发布日期、状态、优先级和正文描述。
4.  通过页面右上角入口跳转到方案提交流程。

**说明：**

1.  公开需求的状态来自后台 `tech-needs` 集合。
2.  状态包括 `开放中`、`推进中`、`已关闭`。
3.  后台一旦更新需求状态，公开站与方案详情中的关联需求状态会同步变化。

### 4.3 提交方案引导页

地址：`/submit`

该页本身不直接提交数据，只承担引导作用：

1.  未登录用户会看到提交说明和登录 / 注册入口。
2.  已登录用户访问该页时，系统会自动跳转到 `/dashboard/proposals/new`。
3.  如果是从某个需求详情页进入，系统会自动携带 `need` 参数，将目标需求预选到提案表单中。

### 4.4 生态伙伴页与全部合作伙伴目录

地址：

1.  `/ecosystem`
2.  `/ecosystem/directory`

使用方式：

1.  `/ecosystem` 只展示金牌战略伙伴。
2.  点击“查看全部合作伙伴”后进入 `/ecosystem/directory`。
3.  完整目录按四个层级展示：`金牌战略伙伴`、`认证合作伙伴`、`生态合作伙伴`、`其他合作伙伴`。
4.  公网页面仅做统一 SVG / Logo 展示，不从前台直接跳转外部官网。

### 4.5 联合创新案例

地址：`/cases`

1.  页面展示案例封面、合作伙伴名称、领域、发布时间和摘要。
2.  点击任意卡片可进入案例详情页。
3.  案例数据来源于后台 `case-studies` 集合。

### 4.6 合作流程

地址：`/process`

该页用于对外说明四步协同流程：

1.  提交方案。
2.  技术评估。
3.  PoC 验证。
4.  导入供应链。

## 5. 账号注册与登录

### 5.1 注册前提

生产环境当前只支持以下身份标识：

1.  邮箱。
2.  中国大陆手机号。

不支持用户名直接登录。

注册时必须满足以下条件：

1.  联系人姓名至少 2 个字符。
2.  用户名至少 2 个字符，只允许字母、数字、下划线和短横线。
3.  公司名称至少 2 个字符。
4.  密码至少 6 位。
5.  确认密码必须与登录密码一致。
6.  邮箱验证码或短信验证码至少完成一种。

### 5.2 注册合作伙伴账号

地址：`/register`

注册页分为三个标签步骤：

1.  `基础信息`
2.  `邮箱验证`
3.  `手机验证`

推荐操作顺序如下：

1.  先在 `基础信息` 中填写联系人姓名、用户名、公司名称、登录密码和确认密码。
2.  点击“下一步”进入验证步骤。
3.  在 `邮箱验证` 中填写邮箱，发送并输入邮箱验证码。
4.  或在 `手机验证` 中填写手机号，发送并输入短信验证码。
5.  至少完成一种验证后，点击“创建合作伙伴账号”。
6.  注册成功后，系统会自动跳转到登录页，并预填刚完成注册的邮箱或手机号。

**补充说明：**

1.  邮箱和短信验证码均为 6 位码。
2.  验证码有效期为 5 分钟。
3.  单个通道发送后有 60 秒冷却时间。
4.  用户可以同时完成邮箱和手机双通道绑定，但不是强制要求。

### 5.3 密码登录

地址：`/login`

在 `邮箱/手机密码登录` 标签下完成：

1.  输入已注册邮箱或手机号。
2.  输入登录密码。
3.  点击登录后进入工作台。

**适用说明：**

1.  邮箱注册用户可用邮箱 + 密码登录。
2.  手机注册用户可用手机号 + 密码登录。
3.  同时绑定邮箱与手机的用户，可任选其一作为标识登录。

### 5.4 邮箱 / 短信验证码登录

地址：`/login`

在 `邮箱/短信验证码登录` 标签下完成：

1.  输入已注册邮箱或手机号。
2.  点击发送验证码。
3.  输入收到的 6 位验证码。
4.  验证成功后直接进入工作台。

**系统行为说明：**

1.  如果输入的是邮箱，系统发送邮箱验证码。
2.  如果输入的是手机号，系统发送短信验证码。
3.  如果验证码正确，但后台不存在对应账号，页面会提示该账号未注册，并提供“去注册”跳转按钮。

## 6. 合作伙伴工作台操作说明

### 6.1 进入工作台

登录成功后默认进入 `/dashboard`。

合作伙伴在左侧通常可见以下菜单：

1.  `概览`
2.  `方案管理`
3.  `个人设置`

### 6.2 概览页

地址：`/dashboard`

合作伙伴可在该页查看：

1.  当前账号相关的方案数量。
2.  平台公开需求数量。
3.  生态伙伴数量。
4.  联合案例数量。
5.  最近提交或最近变更状态的方案列表。

**说明：**

1.  合作伙伴只会看到自己提交的方案记录。
2.  点击“查看详情”可进入方案详情页。

### 6.3 提交新方案

地址：`/dashboard/proposals/new`

方案表单包含以下主要字段：

1.  方案类型。
2.  关联需求。
3.  方案标题。
4.  技术描述。
5.  附件上传。
6.  联系人姓名。
7.  联系邮箱。
8.  公司名称。

**具体填写说明如下：**

1.  `方案类型` 可选：`响应公开需求`、`开放式技术自荐`、`寻求战略投资`、`申请加入生态联盟`。
2.  `关联需求` 可为空；若从需求详情页进入则默认带入。
3.  `方案标题` 应尽量完整明确，便于评审分流。
4.  `技术描述` 至少 20 个字符，建议写明技术优势、成熟度、验证情况和相对竞品差异。
5.  `附件上传` 支持多文件上传，当前前端接受：`TXT`、`PDF`、`PPT`、`PPTX`、`DOC`、`DOCX`、`ZIP`、`RAR`。
6.  选中的附件会以表格形式显示名称、大小和取消按钮。
7.  提交成功后会自动跳转到新建方案的详情页。

**附件规则说明：**

1.  附件最终统一保存在后台 `media` 集合中。
2.  `proposals` 集合中的 `attachments` 字段保存的是与 `media` 的关系。
3.  `TXT` 附件在下载时按文件下载处理，不在浏览器内直接预览。
4.  `media` 会按业务模块自动归档，方案附件进入 `document/proposals/`，伙伴 Logo / SVG 进入各自专属目录。

### 6.4 查看方案列表

地址：`/dashboard/proposals`

合作伙伴可以看到：

1.  自己提交的全部方案。
2.  每条方案的标题、公司、提交时间和当前状态。
3.  若方案关联了某个需求，可看到该需求的当前状态徽标。

**方案状态说明：**

1.  `待评审`
2.  `评审中`
3.  `已通过`
4.  `已驳回`

### 6.5 查看方案详情

地址：`/dashboard/proposals/{id}`

详情页可查看：

1.  方案基础信息。
2.  联系人、邮箱、公司、提交时间。
3.  技术描述全文。
4.  关联需求及其状态。
5.  附件列表与下载入口。
6.  当前评审意见。

**说明：**

1.  合作伙伴只能查看自己提交的方案详情。
2.  若没有上传附件，页面会显示“当前没有上传附件”。

### 6.6 修改个人资料

地址：`/dashboard/settings`

可维护字段包括：

1.  联系人姓名。
2.  用户名。
3.  公司名称。
4.  联系邮箱。
5.  联系手机。

**保存规则：**

1.  用户名仍然必须满足平台格式要求。
2.  邮箱必须合法。
3.  手机号必须是 11 位中国大陆手机号。
4.  若修改邮箱或手机号，系统会重置该通道的已验证状态。
5.  账号至少需要保留一种可验证的登录方式。

## 7. 评审员操作说明

### 7.1 角色定位

生产环境中的评审员主要负责方案评审，不负责通过中台发布技术需求。

评审员在工作台主要使用以下页面：

1.  `/dashboard`
2.  `/dashboard/proposals`
3.  `/dashboard/proposals/{id}`
4.  `/dashboard/settings`

### 7.2 查看全量方案

地址：`/dashboard/proposals`

评审员可以：

1.  查看平台全部方案记录。
2.  看到每条方案的基础信息与当前状态。
3.  进入详情页开展评审。

### 7.3 填写评审结果

地址：`/dashboard/proposals/{id}`

评审员进入方案详情后，可在页面底部看到评审表单。评审流程如下：

1.  阅读方案标题、描述、关联需求和附件。
2.  在评审表单中填写评审意见。
3.  选择新的流转状态：`待评审`、`评审中`、`已通过`、`已驳回`。
4.  点击保存后，系统会同步更新评审意见和状态流转。

**说明：**

1.  评审意见对合作伙伴可见。
2.  方案状态变更后，列表页和详情页都会反映最新状态。

## 8. 管理员操作说明

### 8.1 管理员工作台范围

管理员在中台可使用：

1.  `/dashboard`
2.  `/dashboard/proposals`
3.  `/dashboard/settings`
4.  `/dashboard/partners`
5.  `/dashboard/users`

管理员还需要进入 `/admin` 完成正式主数据维护。

### 8.2 方案管理

管理员在 `/dashboard/proposals` 与评审员拥有相同的全量方案视图和评审能力。

管理员额外可通过 `/admin/collections/proposals` 完成以下动作：

1.  查看提案原始字段值。
2.  查看 `attachments` 与 `media` 的关系。
3.  核对 `submittedBy`、`reviewedBy` 等后台字段。

### 8.3 伙伴管理

工作台地址：`/dashboard/partners`

该页面主要用于运营视角查看，不负责完整字段维护。正式维护入口如下：

1.  `/admin/collections/partners`

在后台维护合作伙伴时，重点字段包括：

1.  `name`：公开展示名称。
2.  `brandPreset`：优先使用的 SVG 品牌预设。
3.  `logo`：未使用预设时可上传 Logo 文件。
4.  `website`：官网链接，仅后台保留，不作为公开页点击跳转。
5.  `category`：伙伴类型。
6.  `tier`：展示层级。
7.  `description`：对外说明。
8.  `products`：合作方向 / 关键词。
9.  `sortOrder`：排序权重。

**补充说明：**

1.  伙伴相关媒体统一归入 `partners` 模块。
2.  SVG 字标与普通 Logo 会自动进入不同物理目录，便于后续资源管理与替换。

### 8.4 用户管理

工作台地址：`/dashboard/users`

该页面提供账号运营视图。正式编辑入口如下：

1.  `/admin/collections/users`

在后台可维护的重点字段包括：

1.  `username`
2.  `email`
3.  `phone`
4.  `name`
5.  `company`
6.  `role`
7.  `emailVerifiedAt`
8.  `phoneVerifiedAt`

**建议：**

1.  普通资料查看可在工作台完成。
2.  角色切换、验证状态核对、删除用户等操作应在 Admin 中完成。

### 8.5 生产环境中的技术需求发布

这是生产环境与本机开发环境最重要的差异点之一。

生产环境当前的正确做法是：

1.  登录 `/admin`。
2.  进入 `内容资产` 分组下的 `tech-needs` 集合。
3.  点击创建或进入某条记录编辑。
4.  填写或维护以下字段：`title`、`priority`、`domain`、`productLine`、`description`、`status`、`publishedAt`。
5.  保存后，系统会自动生成 `needId`，格式为 `RD-年份-流水号`。
6.  保存完成后，公开站 `/needs` 和方案详情中的关联需求状态会读取最新结果。

**字段说明：**

1.  `needId` 为只读字段，自动生成，例如 `RD-2026-001`。
2.  `priority` 当前包括：`急需解决`、`开放探索`、`联合预研`。
3.  `status` 当前包括：`开放中`、`推进中`、`已关闭`。
4.  `publishedAt` 决定公开需求的发布时间排序。

### 8.6 管理后台登录和退出

管理员使用内部分配的 Admin 后台账号访问：

1.  `/admin/login`

**建议：**

1.  仅使用管理员账号登录后台。
2.  内容维护完成后主动退出，避免共享终端会话残留。

## 9. 生产环境中的数据联动规则

### 9.1 Tech Needs 与公开站联动

1.  `tech-needs` 集合中的数据直接决定公开站 `/needs` 的展示内容。
2.  `status` 更新后，前台需求卡片和方案详情关联状态同步变化。
3.  `publishedAt` 变更会影响公开排序。
4.  若后续新增需求图片资源，后台 `media` 会按 `tech-needs` 模块自动归档到专属图片目录。

### 9.2 Proposals 与 Media 联动

1.  前台上传的提案附件会先进入 `media`。
2.  `proposals.attachments` 保存的是媒体关系，不是独立文件副本。
3.  因此前台附件、后台 proposals 记录和后台 media 记录本质上是同一批文件资产。
4.  `media` 后台会显示所属模块、资产分类和物理存储路径，便于按 `proposals / partners / case-studies / users / tech-needs` 分域管理。

### 9.3 Users 与登录方式联动

1.  用户可通过邮箱或手机号作为登录标识。
2.  只要后台存在已注册用户且验证码正确，验证码登录即可生效。
3.  若后台找不到账号，系统会提示去注册，不会自动创建新账号。

## 10. 常见操作问题

### 10.1 为什么注册时无法直接用用户名登录

因为当前平台明确关闭了用户名登录入口，只保留：

1.  邮箱 / 手机密码登录。
2.  邮箱 / 短信验证码登录。

### 10.2 为什么注册时必须做邮箱或手机验证

因为系统需要确保至少有一种可验证登录通道，便于：

1.  登录。
2.  通知。
3.  找回或后续身份确认。

### 10.3 为什么修改邮箱或手机后需要重新验证

因为系统会在资料保存时重置对应通道的验证状态，避免旧验证状态直接沿用到新联系方式。

### 10.4 为什么管理员在工作台里看不到需求发布页面

因为生产环境当前尚未部署中台版 `需求发布` 页面；需求发布仍通过 admin 管理后台完成。详细差异见：

[local-vs-production-differences.md](https://www.qianwen.com/chat/local-vs-production-differences.md)

### 10.5 为什么附件在后台既出现在 Proposals 里，也出现在 Media 里

因为提案附件的设计是：

1.  文件实体统一存放在 `media` 集合。
2.  `proposals.attachments` 通过关系字段引用这些媒体。
