# Open-Innovation-Platform 生产环境用户操作手册

> 版本：`2026-04-30 / package 2.0.0`
> 撰稿：Platform Team
> 环境口径：生产环境
> 地址：`https://openinnovation.example.com/`

> 特别说明
>
> 1. 本文档默认面向当前生产环境的实际使用者，重点描述可执行操作，不写研发理想态。
> 2. 本机开发环境默认域名为 `https://innovation.example.com`，若存在未同步生产的能力，请以 [local-vs-production-differences.md](./local-vs-production-differences.md) 为准。
> 3. 生产环境当前仍属于公司域内访问场景，公网正式开放时只需要替换域名、证书与允许来源配置，业务操作方式不变。

1. 公开站访客。
2. 已注册合作伙伴。
3. 平台评审员。
4. 平台管理员。

## 4. 公开站使用说明

### 4.1 首页

首页承担平台总入口作用，关键内容如下：

1. 左上角展示品牌 Logo，右上角可切换深浅主题。
2. 首屏按钮可直接进入技术需求大厅或伙伴合作入口。
3. 首页会展示精选技术需求、合作伙伴矩阵与案例入口。
4. “OIP 全球合作伙伴联盟”区域只展示精选伙伴，点击底部按钮可进入完整目录页。

### 4.2 技术需求大厅

地址：`/needs`

用户可完成以下操作：

1. 浏览全部公开需求。
2. 按领域筛选需求，当前分类包括 `电机控制`、`传感器技术`、`新材料 / 工艺`、`AI 与算法`。
3. 进入需求详情页查看需求编号、优先级、产品线、发布时间与正文描述。
4. 从需求详情页直接跳转到方案提交流程。

说明：

1. 公开需求状态直接来自后台 `tech-needs.status`。
2. 当前状态包括 `开放中`、`推进中`、`已关闭`。
3. 后台一旦更新需求状态，公开页、方案列表和方案详情中的关联状态会同步刷新。

### 4.3 提交方案引导页

地址：`/submit`

该页用于引导，不直接落业务数据：

1. 未登录用户会看到登录与注册入口。
2. 已登录用户访问时，系统会自动跳转至 `/dashboard/proposals/new`。
3. 若是从需求详情页进入，会自动带上 `need` 参数，将目标需求预选到表单中。

### 4.4 生态伙伴页与完整目录

地址：

1. `/ecosystem`
2. `/ecosystem/directory`

使用方式：

1. `/ecosystem` 仅展示金牌战略伙伴。
2. 点击“查看全部合作伙伴”后进入 `/ecosystem/directory`。
3. 完整目录按 `金牌战略伙伴`、`认证合作伙伴`、`生态合作伙伴`、`其他合作伙伴` 四个层级展示。
4. 公开页的伙伴图标仅承担展示作用，不从前台直接跳出官网。

### 4.5 联合创新案例

地址：`/cases`

1. 页面展示案例封面、合作伙伴名称、领域、发布时间和摘要。
2. 点击卡片可进入案例详情页。
3. 案例数据来源于后台 `case-studies` 集合。

### 4.6 合作流程

地址：`/process`

该页对外说明标准流程：

1. 提交方案。
2. 技术评估。
3. PoC 验证。
4. 供应链导入。

## 5. 账号注册与登录

### 5.1 登录标识约束

当前平台只允许以下两类标识作为登录入口：

1. 邮箱。
2. 中国大陆手机号。

不开放用户名直接登录。

### 5.2 注册合作伙伴账号

地址：`/register`

注册页分为三个标签步骤：

1. `基础信息`
2. `邮箱验证`
3. `手机验证`

建议操作顺序：

1. 在 `基础信息` 中填写联系人姓名、用户名、公司名称、密码和确认密码。
2. 点击“下一步”进入验证步骤。
3. 在 `邮箱验证` 中填写邮箱、发送验证码并完成验证。
4. 或在 `手机验证` 中填写手机号、发送验证码并完成验证。
5. 邮箱和手机至少完成一种验证后，点击“创建合作伙伴账号”。
6. 注册成功后，系统会自动跳转回登录页。

注册校验规则：

1. 联系人姓名至少 2 个字符。
2. 用户名至少 2 个字符，只允许字母、数字、下划线和短横线。
3. 公司名称至少 2 个字符。
4. 密码至少 6 位。
5. 确认密码必须与密码一致。
6. 邮箱或手机至少填写一种。
7. 邮箱验证码或短信验证码至少完成一种。

补充说明：

1. 邮箱和短信验证码均为 6 位。
2. 验证码有效期为 5 分钟。
3. 单个通道发送后有 60 秒冷却时间。
4. 用户可同时绑定邮箱与手机号，但不是强制要求。

### 5.3 邮箱/手机密码登录

地址：`/login`

在 `邮箱/手机密码登录` 标签下完成：

1. 输入已注册邮箱或手机号。
2. 输入登录密码。
3. 点击登录后进入工作台。

适用说明：

1. 邮箱注册用户可用邮箱加密码登录。
2. 手机注册用户可用手机号加密码登录。
3. 同时绑定邮箱与手机号的用户，可任选其一作为登录标识。

### 5.4 邮箱/短信验证码登录

地址：`/login`

在 `邮箱/短信验证码登录` 标签下完成：

1. 输入已注册邮箱或手机号。
2. 点击发送验证码。
3. 输入收到的 6 位验证码。
4. 验证成功后直接进入工作台。

系统行为说明：

1. 输入邮箱时，系统发送邮箱验证码。
2. 输入手机号时，系统发送短信验证码。
3. 验证码正确但后台不存在对应账号时，页面会提示账号未注册，并提供“去注册”跳转按钮。
4. 登录验证码只用于已有账号登录，不会自动创建新用户。

## 6. 合作伙伴工作台操作说明

### 6.1 进入工作台

登录成功后默认进入 `/dashboard`。

合作伙伴通常可见以下菜单：

1. `概览`
2. `方案管理`
3. `个人设置`

### 6.2 概览页

地址：`/dashboard`

合作伙伴可在该页查看：

1. 当前账号相关的方案数量。
2. 平台公开需求数量。
3. 生态伙伴数量。
4. 联合案例数量。
5. 最近提交或最近变更状态的方案列表。

说明：

1. 合作伙伴只会看到自己提交的方案记录。
2. 点击方案可进入详情页。

### 6.3 提交新方案

地址：`/dashboard/proposals/new`

主要字段如下：

1. 方案类型。
2. 关联需求。
3. 方案标题。
4. 技术描述。
5. 附件上传。
6. 联系人姓名。
7. 联系邮箱。
8. 公司名称。

填写规则：

1. `方案类型` 可选：`响应公开需求`、`开放式技术自荐`、`寻求战略投资`、`申请加入生态联盟`。
2. `关联需求` 可为空；若从需求详情页进入则会自动带入。
3. `技术描述` 至少 20 个字符。
4. 附件支持多文件上传。
5. 当前允许的附件类型为 `TXT`、`PDF`、`PPT`、`PPTX`、`DOC`、`DOCX`、`ZIP`、`RAR`。
6. 当前单文件业务上限为 `100MB`。
7. 选中的附件会在前端以紧凑表格显示文件名、大小和移除按钮。

附件规则说明：

1. 附件实体统一保存于后台 `media` 集合。
2. `proposals.attachments` 保存的是与 `media` 的关系，不重复存一份副本。
3. `TXT` 附件下载时会强制按文件下载，不在浏览器中直接预览。
4. 方案附件会自动归档到 `media/document/proposals/` 对应路径体系。

### 6.4 查看方案列表

地址：`/dashboard/proposals`

合作伙伴可看到：

1. 自己提交的全部方案。
2. 每条方案的标题、公司、提交时间和当前状态。
3. 若方案关联了某条需求，可看到该需求当前状态。

方案状态说明：

1. `待评审`
2. `评审中`
3. `已通过`
4. `已驳回`

### 6.5 查看方案详情

地址：`/dashboard/proposals/{id}`

详情页可查看：

1. 方案基础信息。
2. 联系信息与提交时间。
3. 技术描述全文。
4. 关联需求及其状态。
5. 附件列表与下载入口。
6. 当前评审意见。
7. 提交与评审时间线。

说明：

1. 合作伙伴只能查看自己提交的方案详情。
2. 若没有上传附件，页面会显示空状态提示。

### 6.6 修改个人资料

地址：`/dashboard/settings`

当前用户可维护：

1. 联系人姓名。
2. 用户名。
3. 公司名称。
4. 联系邮箱。
5. 联系手机。

保存规则：

1. 用户名仍需满足平台格式规则。
2. 邮箱必须合法。
3. 手机号必须是 11 位中国大陆手机号。
4. 若修改邮箱或手机号，系统会重置对应通道的验证状态。
5. 非管理员账号必须至少保留一种已验证登录方式。

## 7. 评审员操作说明

### 7.1 角色定位

评审员主要负责方案评审，不负责公开站访客运营，也不默认通过工作台发布需求。

评审员常用页面：

1. `/dashboard`
2. `/dashboard/proposals`
3. `/dashboard/proposals/{id}`
4. `/dashboard/settings`

### 7.2 查看全量方案

地址：`/dashboard/proposals`

评审员可以：

1. 查看平台全部方案记录。
2. 看到每条方案的基础信息与当前状态。
3. 进入详情页开展评审。

### 7.3 填写评审结果

地址：`/dashboard/proposals/{id}`

评审流程如下：

1. 阅读方案标题、描述、关联需求和附件。
2. 在页面中填写评审意见。
3. 选择新的流转状态：`待评审`、`评审中`、`已通过`、`已驳回`。
4. 点击保存后，系统会同步更新评审意见、方案状态和评审时间线。

说明：

1. 评审意见对对应合作伙伴可见。
2. 每次状态变更都会沉淀到时间线中，记录人员、时间、状态与意见。

## 8. 管理员操作说明

### 8.1 管理员工作台范围

管理员在中台可使用：

1. `/dashboard`
2. `/dashboard/proposals`
3. `/dashboard/settings`
4. `/dashboard/partners`
5. `/dashboard/users`

正式主数据维护仍以 `/admin` 为准。

### 8.2 方案管理

管理员在 `/dashboard/proposals` 中拥有与评审员一致的方案评审能力。

在 `/admin/collections/proposals` 中，管理员还可完成：

1. 查看提案原始字段值。
2. 查看 `attachments` 与 `media` 的关系。
3. 查看 `submittedBy`、`reviewedBy`、`reviewTimeline` 等后台字段。
4. 删除提案或复制提案用于后台运维处理。

### 8.3 伙伴管理

工作台入口：`/dashboard/partners`

该页主要用于运营视图查看，不承担完整字段维护。正式入口：

1. `/admin/collections/partners`

重点字段包括：

1. `name`：公开展示名称。
2. `brandPreset`：优先使用的 SVG 品牌预设。
3. `logo`：未使用预设时的自定义 Logo 文件。
4. `website`：官网链接，仅后台保留。
5. `category`：伙伴类型。
6. `tier`：展示层级。
7. `description`：对外说明。
8. `products`：合作方向或关键词。
9. `sortOrder`：排序权重。

说明：

1. 伙伴 Logo、SVG 与图片附件会归入 `partners` 模块专属目录。
2. 前台伙伴目录统一以 SVG 或标准 Logo 卡片方式展示。

### 8.4 用户管理

工作台入口：`/dashboard/users`

该页提供账号运营视图。正式编辑入口：

1. `/admin/collections/users`

重点字段包括：

1. `username`
2. `email`
3. `phone`
4. `name`
5. `company`
6. `role`
7. `emailVerifiedAt`
8. `phoneVerifiedAt`
9. `lastAccessAt`

建议：

1. 普通资料查看可在工作台完成。
2. 角色切换、验证状态核对、删除用户等操作应在 Admin 后台完成。

### 8.5 技术需求发布

生产环境下的正式发布入口为：

1. 登录 `/admin`
2. 进入 `/admin/collections/tech-needs`
3. 创建或编辑需求
4. 填写 `title`、`priority`、`domain`、`productLine`、`description`、`status`、`publishedAt`
5. 保存后由系统自动生成 `needId`

字段说明：

1. `needId` 自动生成，格式为 `RD-年份-流水号`，例如 `RD-2026-001`。
2. `priority` 当前包括：`急需解决`、`开放探索`、`联合预研`。
3. `status` 当前包括：`开放中`、`推进中`、`已关闭`。
4. `publishedAt` 影响公开排序。

### 8.6 管理后台登录与退出

管理员使用内部分配账号访问：

1. `/admin/login`

建议：

1. 管理后台只用于内部人员。
2. 内容维护完成后应主动退出，避免共享终端残留登录态。

## 9. 数据联动规则

### 9.1 Tech Needs 与公开站联动

1. `tech-needs` 集合直接决定 `/needs` 的公开内容。
2. `status` 更新后，公开需求卡片、需求详情和方案关联状态同步变化。
3. `publishedAt` 更新后，会影响需求列表排序。

### 9.2 Proposals 与 Media 联动

1. 前台上传的提案附件先写入 `media`。
2. `proposals.attachments` 保存的是媒体关系。
3. 删除提案时，会同步处理关联附件。
4. `media` 后台会展示所属模块、资产分类和物理存储路径，便于按模块管理。

### 9.3 Users 与登录方式联动

1. 用户可通过邮箱或手机号作为登录标识。
2. 验证码登录只对后台已存在的账号生效。
3. 资料页修改邮箱或手机后，对应验证状态会重置。
4. 登录成功后，系统会刷新 `lastAccessAt`。

## 10. 常见问题

### 10.1 为什么不能用用户名登录

因为平台当前明确关闭了用户名登录入口，只保留：

1. 邮箱/手机密码登录。
2. 邮箱/短信验证码登录。

### 10.2 为什么注册时必须做邮箱或手机验证

因为系统必须保留至少一种可验证登录通道，用于：

1. 登录。
2. 通知。
3. 后续身份确认。

### 10.3 为什么修改邮箱或手机后需要重新验证

因为系统会在资料保存时主动重置新通道的验证状态，避免旧验证结果沿用到新联系方式。

### 10.4 为什么后台同时能在 Proposals 和 Media 中看到附件

因为提案附件的设计是：

1. 文件实体统一保存在 `media` 集合。
2. `proposals.attachments` 通过关系字段引用这些媒体。

这属于正常设计，不是重复上传。

### 10.5 需求状态为什么会影响方案列表

因为方案详情和方案列表会同步读取其关联需求的当前状态，便于合作伙伴和评审员判断该需求是否仍处于开放窗口。
