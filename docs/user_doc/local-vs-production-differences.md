# 本机开发环境与生产环境差异说明

更新日期：`2026-04-30`

## 1. 核对基线

| 项目             | 本机开发环境                             | 生产环境                                     |
| ---------------- | ---------------------------------------- | -------------------------------------------- |
| 访问域名         | `https://innovation.example.com` | `https://openinnovation.example.com` |
| 文档默认口径     | 当前仓库主线代码                         | 已实际部署并经授权上线的能力                 |
| 当前差异判断方式 | 以本仓库 `main` 和本机运行状态为准       | 以生产服务器当前实际部署结果为准             |

## 2. 差异总表

以下项目属于“当前仓库主线已实现，但生产环境需确认是否已经同步部署”的能力：

| 对比项                    | 生产环境操作口径                                        | 本机开发环境当前代码口径                                        | 影响                                                   |
| ------------------------- | ------------------------------------------------------- | --------------------------------------------------------------- | ------------------------------------------------------ |
| 中台 `需求发布` 页面      | 默认仍以 `/admin/collections/tech-needs` 为正式发布入口 | 仓库中已存在 `/dashboard/needs` 与 `/api/dashboard/tech-needs*` | 若生产未升级，则业务培训不能把中台需求发布写成既有能力 |
| 管理员 / 评审员概览页     | 以生产已部署页面为准                                    | 当前仓库概览页可展示“最新技术需求”模块                          | 演示截图、培训材料和验收路径需要区分                   |
| 后台 `users` 最后访问时间 | 需确认生产是否已同步 `lastAccessAt` 字段与列表列        | 当前仓库已支持 `users.lastAccessAt` 与后台“最后访问时间”列      | 若生产未升级，则后台用户表可能还没有该列               |
| 方案详情评审时间线        | 需确认生产是否已同步 `reviewTimeline` 的前台展示        | 当前仓库已在提案详情页展示提交与评审的时间线                    | 若生产未升级，则前台可能只看到状态和评审意见           |
| 附件单文件上限            | 需确认生产是否已同步 `100MB / 120mb / 120M` 三层限制    | 当前仓库已统一为单文件 `100MB`                                  | 若生产未升级，超过旧阈值的文件可能仍上传失败           |

## 3. Tech Needs 管理差异

### 3.1 生产环境

生产环境当前应按以下路径维护需求：

1. 登录 `/admin`
2. 进入 `/admin/collections/tech-needs`
3. 在 Payload Admin 中创建、修改和发布需求

特点：

1. `tech-needs` 集合本身的 Payload 权限仍然是 `admin` 才能创建、更新、删除
2. 评审员在生产环境中默认不承担需求发布职责
3. 需求状态更新后，公开站 `/needs` 和方案详情中的关联需求状态会正常同步

### 3.2 本机开发环境

本机当前仓库额外实现了中台版需求运营台：

1. 页面：`/dashboard/needs`
2. API：`/api/dashboard/tech-needs`
3. API：`/api/dashboard/tech-needs/[id]`

特点：

1. 页面允许 `admin` 和 `reviewer` 登录后访问
2. API 内部使用受控的 `overrideAccess: true` 写入 Payload
3. 保存后同样会同步影响公开站需求大厅与方案关联状态视图

## 4. 工作台页面差异

### 4.1 管理员视角

生产环境管理员工作台默认应视为：

1. 概览
2. 方案管理
3. 个人设置
4. 伙伴管理
5. 用户管理

本机当前仓库中，管理员还可能看到：

6. 需求发布

### 4.2 评审员视角

生产环境评审员工作台默认应视为：

1. 概览
2. 方案管理
3. 个人设置

本机当前仓库中，评审员还可能看到：

4. 需求发布

### 4.3 概览页面

生产环境概览页以实际部署结果为准。

本机当前仓库额外确认了以下能力：

1. 四个统计卡片带图标
2. 新增“最新技术需求”模块
3. 对管理员和评审员，需求模块可直接进入 `/dashboard/needs`

## 5. 文档使用口径建议

### 5.1 面向业务验收或最终用户

统一使用生产环境文档口径：

1. 域名写 `https://openinnovation.example.com`
2. 技术需求发布写成管理员在 `/admin/collections/tech-needs` 中维护
3. 未经确认部署的中台需求发布、100MB 上传和后台新列，不直接写成生产既有能力

### 5.2 面向研发或上线准备

需要同时参考本文件，重点关注：

1. 本机领先生产的功能点
2. 生产尚未确认同步的工作台需求管理能力
3. 上传链路三层限制是否都已同步
4. `users.lastAccessAt` 与 `proposals.reviewTimeline` 是否已部署到目标环境

## 6. 后续上线判断标准

只有在生产环境完成明确授权部署，并通过以下验收后，才可以把对应能力转写为“生产正式口径”：

1. `/dashboard/needs` 页面可正常访问和保存
2. 概览页中的“最新技术需求”模块已部署
3. `users` 后台列表出现“最后访问时间”列
4. `30MB` 以上附件上传在生产域名下可成功
5. 方案详情页中的评审时间线可见
