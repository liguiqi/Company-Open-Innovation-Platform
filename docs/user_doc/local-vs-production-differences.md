# 本机开发环境与生产环境差异说明

## 1. 核对基线

| 项目         | 本机开发环境                                                         | 生产环境                                                                   |
| ------------ | -------------------------------------------------------------------- | -------------------------------------------------------------------------- |
| 访问域名     | `https://innovation.example.com`                             | `https://openinnovation.example.com`                               |
| 当前代码基线 | `a8437b7 feat(dashboard): integrate tech needs workspace management` | `b21d518 fix(runtime): align production auth and user lifecycle stability` |
| 差异结论     | 本机领先生产 2 个提交                                                | 生产尚未部署本机最新中台 `Tech Needs` 管理能力                             |

本机相对生产多出的两个提交如下：

1. `2b589a7 chore(sync): align local workspace with current production baseline`
2. `a8437b7 feat(dashboard): integrate tech needs workspace management`

其中：

1. `2b589a7` 主要用于本机工作区与生产基线对齐，非新增业务能力。
2. `a8437b7` 是当前最核心的功能差异来源，新增了中台版 `Tech Needs` 管理页面与配套 API。

## 3. Tech Needs 管理差异

### 3.1 生产环境

生产环境当前应按以下路径维护需求：

1. 登录 `/admin`。
2. 进入 `/admin/collections/tech-needs`。
3. 在 Payload Admin 中创建、修改和发布需求。

特点：

1. `tech-needs` 集合本身的 Payload 权限仍然是 `admin` 才能创建、更新、删除。
2. 评审员在生产环境中不承担需求发布职责。
3. 需求状态更新后，公开站 `/needs` 和方案详情中的关联需求状态会正常同步。

### 3.2 本机开发环境

本机新增了中台版需求运营台：

1. 页面：`/dashboard/needs`
2. 新增 API：`/api/dashboard/tech-needs`
3. 新增 API：`/api/dashboard/tech-needs/[id]`

特点：

1. 页面允许 `admin` 和 `reviewer` 登录后访问。
2. API 中通过自定义权限判断，允许 `admin` 和 `reviewer` 直接创建或编辑需求。
3. API 内部使用 `overrideAccess: true` 写入 Payload，因此本机中台能力突破了原始集合中 `admin only` 的写权限限制。
4. 保存后同样会同步影响公开站需求大厅与方案关联状态视图。

结论：

1. 本机开发环境已经形成“中台需求发布”能力。
2. 生产环境仍停留在“Payload Admin 发布需求”能力。
3. 任何培训、验收、用户手册和上线说明，都必须把生产口径写成“管理员到 `/admin/collections/tech-needs` 操作”。

## 4. 工作台页面差异

### 4.1 管理员视角

生产环境管理员工作台侧边栏：

1. 概览
2. 方案管理
3. 个人设置
4. 伙伴管理
5. 用户管理

本机开发环境管理员工作台侧边栏：

1. 概览
2. 方案管理
3. 个人设置
4. 需求发布
5. 伙伴管理
6. 用户管理

### 4.2 评审员视角

生产环境评审员工作台侧边栏：

1. 概览
2. 方案管理
3. 个人设置

本机开发环境评审员工作台侧边栏：

1. 概览
2. 方案管理
3. 个人设置
4. 需求发布

### 4.3 概览页面

生产环境概览页面当前内容：

1. 四个基础统计卡片：
   `方案总数`、`公开需求`、`生态伙伴`、`联合案例`。
2. 最近方案列表。

本机开发环境概览页面新增内容：

1. 同样的四个统计卡片，但增加图标样式。
2. 新增“最新技术需求”模块。
3. 需求模块使用 2 列布局，展示最新 3 条需求。
4. 管理员和评审员可从该模块直接进入 `/dashboard/needs`。

## 5. 文档使用口径建议

### 5.1 面向业务验收或最终用户

统一使用生产环境文档口径：

1. 域名使用 `https://openinnovation.example.com`。
2. 技术需求发布写成管理员在 `/admin/collections/tech-needs` 中维护。
3. 不把 `/dashboard/needs` 视为生产已上线能力。

### 5.2 面向研发或上线准备

需要同时参考本文件，重点关注：

1. 本机领先生产的功能点。
2. 生产尚未部署的中台需求发布能力。
3. 若后续计划将本机版本上线，需要同步验证：
   角色权限、侧边栏菜单、概览页结构和 `/api/dashboard/tech-needs*` 两组接口。

## 6. 后续上线判断标准

当生产环境升级到至少 `a8437b7` 或更新提交后，才可以将以下内容从“差异说明”转写为“生产操作手册”的正式能力：

1. `/dashboard/needs` 页面。
2. 评审员中台发布 / 编辑需求能力。
3. 概览页中的“最新技术需求”模块。
4. 与 `Tech Needs` 相关的新中台 API。
