# 服务器资源申请清单

更新日期：`2026-04-30`

## 1. 文档用途

本文用于向公司深信服超融合平台申请本项目生产虚拟机资源。

适用项目：

- `Open Innovation Platform`
- 开发环境域名：`innovation.example.com`
- 生产调试域名：`openinnovation.example.com`
- 部署形态：`单机混部`

当前项目实际运行组件包括：

- `Nginx`
- `Next.js 16.2 + Payload CMS 3.82`
- `PostgreSQL`
- `Redis`
- `media/` 上传附件目录

## 2. 申请建议

### 2.1 当前主线版本建议规格

| 项目    | 建议规格                        | 说明                                                                                 |
| ------- | ------------------------------- | ------------------------------------------------------------------------------------ |
| 系统    | `Ubuntu Server 24.04 LTS`       | 推荐使用 LTS 版本，便于与现有部署脚本、`systemd`、`nginx`、`docker compose` 保持一致 |
| CPU     | `8 vCPU`                        | 适合当前单机承载 `Nginx + App + PostgreSQL + Redis` 的正式环境                       |
| 内存    | `16 GB`                         | 推荐与 CPU 同步申请，避免 Node 构建、数据库缓存和 Redis 并存时出现紧张               |
| 系统盘  | `100 GB SSD`                    | 用于系统、运行时、构建产物、日志与基础组件                                           |
| 数据盘  | `200 GB SSD`                    | 用于 PostgreSQL 数据、Redis 持久化、`media/` 上传附件与备份缓存                      |
| 网络    | `1 Gbps 内网` + `100 Mbps` 出口 | 满足 HTTPS 访问、构建拉包、短信/邮件外部调用与日常运维                               |
| IP 需求 | `1 个固定内网 IP`               | 供域名解析与 Nginx 绑定                                                              |

合计建议磁盘：

- `300 GB SSD`

### 2.2 最低可运行规格

如果当前资源紧张，可接受的最低申请规格如下：

| 项目 | 最低规格                                 |
| ---- | ---------------------------------------- |
| 系统 | `Ubuntu Server 22.04 LTS` 或 `24.04 LTS` |
| CPU  | `4 vCPU`                                 |
| 内存 | `8 GB`                                   |
| 磁盘 | `200 GB SSD`                             |
| 网络 | `1 Gbps 内网`                            |

说明：

- `4 vCPU / 8 GB` 仅适合当前阶段低并发使用，不建议作为长期正式环境标准
- 当前单文件附件业务上限已提升到 `100MB`，媒体与备份增长速度会高于早期版本
- 如果继续采用单机数据库和本地附件存储，磁盘不建议低于 `200 GB`

## 3. 系统与网络要求

### 3.1 操作系统要求

建议操作系统：

- `Ubuntu Server 24.04 LTS x86_64`

兼容替代：

- `Ubuntu Server 22.04 LTS x86_64`

原因：

- 当前项目部署文档、服务脚本与排障经验均围绕 Ubuntu LTS 维护
- 现有生产运行方式依赖：
  - `systemd`
  - `nginx`
  - `docker compose`
  - `pnpm / Node.js`

### 3.2 网络要求

入站需求：

- `80/tcp`：HTTP 跳转 HTTPS
- `443/tcp`：正式访问入口

出站需求：

- `443/tcp`：GitHub、npm、阿里云 API、系统更新
- `25/465/587/994/tcp`：SMTP / IMAP 连通性检查
- `53/tcp/udp`：DNS 解析

内网访问建议：

- 虚拟机需具备稳定内网访问能力
- 至少一个固定 IP 用于 `innovation.example.com` / `openinnovation.example.com`
- 建议至少 `1 Gbps` 内网带宽，避免文件上传、构建发布和附件下载时受限

## 4. 资源评估依据

本次建议规格基于当前项目的真实运行形态：

- 应用对外通过 `nginx :443` 提供服务
- Node 应用实际监听 `127.0.0.1:3005`
- 数据库与缓存当前为本机同机部署
- 提案附件、图片与品牌静态资源均保存在本机磁盘
- 当前上传链路已支持 `100MB` 单文件
- 登录、短信、邮件、管理后台、公共站点共用同一套应用实例

因此本项目申请虚拟机时，不应只按“纯前端站点”估算，而应按“单机业务应用 + 数据库 + 缓存 + 附件存储”的方式申请。

## 5. 结论

如果本次目标是申请一台可以直接承接当前正式环境的生产虚拟机，建议提交如下资源：

```text
操作系统：Ubuntu Server 24.04 LTS x86_64
CPU：8 vCPU
内存：16 GB
磁盘：300 GB SSD（系统盘 100 GB + 数据盘 200 GB）
网络：1 Gbps 内网，100 Mbps 出口，固定内网 IP 1 个
```

如果公司当前资源审批偏紧，可先申请：

```text
操作系统：Ubuntu Server 22.04 / 24.04 LTS
CPU：4 vCPU
内存：8 GB
磁盘：200 GB SSD
网络：1 Gbps 内网，固定内网 IP 1 个
```

但从当前版本稳定性、附件增长和后续媒体资产沉淀的角度，仍推荐优先按 `8 vCPU / 16 GB / 300 GB SSD` 执行。
