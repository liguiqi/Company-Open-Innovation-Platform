## 本轮确认

- 当前仓库是单仓全栈项目，Next.js 与 Payload 运行在同一进程内
- 页面、Dashboard 和自定义业务 API 主要通过 Payload Local API 访问数据
- PostgreSQL 是主业务库，Redis 只承担短信 OTP；短信限流本身使用内存限流器
- 媒体文件当前持久化目录是仓库根目录 `media/`，不是 standalone 内部目录
- Payload 真实主表已核对，包括 `users`、`user_groups`、`tech_needs`、`proposals`、`proposals_rels`、`partners`、`case_studies`、`media`

## 当前结论

- 查看后台数据的首选入口仍然是 `/admin`
- 如果需要接口级查看，可用 Payload REST / GraphQL
- 如果需要看真实原始表和关系表，可直接连接 PostgreSQL，但要明确这会绕过 Payload 权限和 Hook

## 认证链路补充

- 登录/注册页继续按官网同源视觉收口，重写右侧表单层级，减少旧版字体与分栏过挤导致的不协调感
- 注册页改为“基础信息 / 邮箱验证 / 手机验证 / 安全设置”四段式结构，保留邮箱验证码或短信验证码至少完成一种的业务规则
- 邮箱验证码复用企业邮 SMTP 运行态：`994 + SSL`，并将 Payload 内置邮件适配器同步到相同配置口径
- 短信验证码正式切换为阿里云 `Dypnsapi SendSmsVerifyCode`，服务端缓存阿里云回传的真实验证码用于注册校验
- 邮箱发码接口调整为“发送成功后再写入 Redis”，避免邮件通道失败时缓存内残留不可达验证码
