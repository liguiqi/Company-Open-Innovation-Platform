# 2026-04-20 开发记录

## 本轮目标

- 将登录页验证码登录从“验证码正确即自动注册”修正为“仅允许已有账号登录”
- 为登录页补充邮箱验证码登录，与短信验证码登录统一到同一标签页
- 将注册页改为基础信息 / 邮箱验证 / 手机验证三段式标签流转，并补齐实时密码校验与注册成功后自动回跳登录

## 本轮调整

- 新增 `/api/auth/login-code/send` 与 `/api/auth/login-code/verify` 两个登录验证码接口，支持根据邮箱或手机号自动选择邮箱验证码或短信验证码通道
- 登录验证码验证成功后，只在 `users` 集合中命中现有账号时创建登录态；账号不存在时返回明确的 `register` 动作与预填注册链接
- 保留注册验证码链路不变，登录验证码与注册验证码分别使用独立 Redis key 前缀，避免场景串用
- 为邮箱新增登录验证码邮件模板，区分注册验证码和登录验证码文案
- 登录页标题调整为“欢迎使用开放创新工作台”，标签文案改为“邮箱/手机密码登录”与“邮箱/短信验证码登录”
- 登录页验证码模式收敛为单一“邮箱或手机号 + 验证码”表单，并在未注册时弹出前往注册的确认弹窗
- 注册页改为三标签结构：基础信息、邮箱验证、手机验证
- 基础信息步骤整合联系人、用户名、公司和安全设置，并加入基于当前后端规则的实时密码长度/一致性校验
- 基础信息未完成时，不允许切入邮箱验证或手机验证步骤
- 邮箱验证页和手机验证页均保留“创建合作伙伴账号”按钮，满足“邮箱或手机任一验证通过即可注册”的业务口径
- 注册成功后自动跳转回登录页，并通过 query 透传默认登录标识和成功提示
- 按验收反馈移除登录页与注册页中非必要的引导说明区块，保留既有登录、注册、验证码和跳转功能不变
