## 关键决策

- Payload Admin 继续沿用 Payload 自身鉴权，公共工作台单独使用 `innovation-session` Cookie，避免两套后台身份边界互相干扰
- 邮箱密码登录仍使用 Payload 校验凭据，但工作台登录态改为自定义 JWT Session，便于 `proxy` 与服务端组件统一鉴权
- 邮箱验证采用自定义 token 流程，避免过度依赖 Payload 默认验证页
- 方案附件采用 `Media` 关系模型，图片公开、文档受限读取

## 风险与限制

- 阿里云短信目前缺少正式 `TemplateCode` 时，会自动回落为开发 mock 模式
- 企业邮箱为真实 SMTP，文档和代码均不入库密钥，只在 `.env.local` 本地配置；若 SMTP 服务端重置连接，邮件发送会降级为不阻断主流程
- 当日版本中 `settings` 页面仍为只读视图；该限制已在 `2026-04-20` 正式版中解除，当前生产环境支持用户自助更新个人资料
